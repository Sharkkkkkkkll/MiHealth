# MiHealth 睡眠智能体系统 · 测试计划

> 版本：v1.0
> 日期：2026-10-21
> 作者：Sharkkkkkkkll

## 1. 测试目标

验证 MiHealth 睡眠智能体系统的核心能力是否达到预期，覆盖：

- 小米健康数据采集与多账号隔离
- AI 睡眠规划（S/P 双锚点 + LLM 决策）
- 睡前提醒（固定五弹 + AI 文案）
- AI 智能闹钟（浅睡/REM 识别、深睡保护、保底、渐进式响铃）
- BLE 直连手环心率与锁屏保活
- 精力/体力算法
- 系统级可靠性（闹钟不依赖 App 存活、启动恢复、幂等保护）

## 2. 测试范围

### 2.1 功能范围

| 模块 | 测试重点 |
|---|---|
| 米桥数据拉取 | 扫码登录、增量同步、滚动窗口、多账号拉取 |
| 仪表盘服务器 | `/api/data`、`/api/sleep`、`/api/hr`、`/api/pull`、`/api/pull_status` |

| 多账号隔离 | 数据、记忆、AI 决策、拉取进程、LLM 日志 |

### 2.2 不测范围

- 小米运动健康 App 本身
- 小米云端接口的稳定性（非官方接口，可能变化）
- 医疗级睡眠分期准确性（本项目使用心率近似信号）

## 4. 测试策略

### 4.1 测试分层

| 层级 | 范围 | 方法 |
|---|---|---|
| 单元测试 | planner/notifier/wake_engine/server 算法 | Python 脚本验证 |
| 集成测试 | Agent ↔ 手机、仪表盘 ↔ 手机 | HTTP 请求验证 |
| 真机测试 | Android 端到端 | 真机安装 + 日志验证 |
| 回归测试 | 历史 bug 修复 | 复现 + 验证 |

### 4.2 测试原则

- 优先验证「不破坏原有生态」：幂等保护、启动恢复
- 优先验证「闹钟可靠」：系统级、不依赖 App 存活
- 优先验证「数据正确」：S/P 锚点、精力算法、睡眠分析
- 真实数据优先：用小米手环实际导出数据验证
- 多账号优先：每个账号的数据、记忆、AI 决策必须隔离

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 小米云端接口变化 | 数据拉取失败 | 保留本地 JSON 缓存，接口变化时降级 |
| BLE 广播不稳定 | 心率断连 | autoConnect + 指数退避重连 + 保底闹钟 |
| 多账号数据污染 | 用户看到别人数据 | 全链路 user_id 隔离 + 账号目录回退 |
| LLM 调用失败 | 规划/文案失败 | 规则中心值兜底 + 本地模板 |
| 系统闹钟被清 | 闹钟不响 | 保底闹钟系统级 + 启动恢复 |
