### 3.1 睡眠规划（planner.py）

**S/P 双锚点**：

```python
# 锚点 S：生理困意（醒来 + 今天清醒时长，比例+质量缩放）
s_clock, med_awake = _sleepiness_anchor()
s_abs = _next_occurrence(s_clock, now_dt) if s_clock is not None else None

# 锚点 P：起床倒推（硬约束起床 − 理想时长）
if wake is not None:
    p_abs = _next_occurrence(wake, now_dt) - ideal

# 融合：以 S 为基准，用耐受性展开选择区间
if p_abs < s_abs:
    # P 更早 → 区间 [S−early, S]
    tol_lo, tol_hi = s_abs - early, s_abs
else:
    # P 更晚 → 区间 [S, S+late]
    tol_lo, tol_hi = s_abs, s_abs + late
```

// 标准 Heart Rate Measurement：flags 第 0 位决定 16/8 位
val flags = v[0].toInt() and 0xFF
val is16Bit = flags and 0x01 != 0
return if (is16Bit) {
    (v[1].toInt() and 0xFF) or ((v[2].toInt() and 0xFF) shl 8)

    v[1].toInt() and 0xFF
}

## 4. 踩过的坑（关键实现教训）

### 4.1 凌晨重规划 bug

**现象**：昨晚计划 00:23 入睡，23:52 弹完 P30 后，00:00:52 被重规划成 03:00。

**根因**：`maybe_generate` 用 `p.date != today` 判断「新的一天」，午夜一过就触发重规划。

**修复**：凌晨保护窗口（00:00-06:00），已有计划只响应参数变化/白天睡眠，不因「新的一天」重规划。

### 4.2 闹钟被吞 bug

**现象**：设入睡时间后第一次响铃正常，第二次不响。

**根因**：`syncFromServer` 的 `version == applied` 静默去重，手动设置时 version 没变导致跳过。

**修复**：加 `force` 参数，手动设置强制重排；`SleepGoalPrefs.save` 去掉内部 fire-and-forget 推送。

### 4.3 心率断连

**现象**：锁屏后第三方心率广播 App 断连，智能闹钟失效。

**根因**：第三方 WebSocket 被系统挂起，重连没生效。

**修复**：改为 BLE 直连手环（标准 GATT），`autoConnect=true` 系统级重连；前台服务 + `PARTIAL_WAKE_LOCK` + WifiLock 保活；20s 假死检测 + 90s 强制重连；保底闹钟不依赖 WakeEngine 存活。

### 4.4 并发写文件 JSONDecodeError

**现象**：`pull_to_json.py` 写 JSON 时，`data_source.load()` 读到半截，偶发崩溃。

**根因**：文件写一半时被读。

**修复**：`data_source.load()` 加重试（3 次，间隔 1s）。

### 4.5 精力条满格战神

**现象**：凌晨精力显示 100%。

**根因**：`_cumulative_awake` 今天没睡眠记录时返回 0。

**修复**：今天没睡眠记录时返回 `now_min`（今天已过分钟数）。

## 5. 代码质量

### 5.1 幂等保护

- `maybe_generate`：计划存在且参数没变 → 返回 None
- `get_or_build_pack`：bed_min 没变 → 不重建
- `pregen_due`：`_REFILLING` 防重入 + copy_pool 去重
- `data_source.load()`：JSON 写一半时重试

### 5.2 启动恢复

`_startup_recovery()` 在 Agent 启动时立即执行：
1. `maybe_generate`：恢复今晚计划
2. `get_or_build_pack`：恢复闹钟包
3. `pregen_due`：恢复即将弹点文案

### 5.3 多用户隔离

- 记忆：`memory_data/<user_id>/`
- 数据：`JSON/<user_id>/`
- 数据库：`mi_fitness_local_<uid>.db`
- 钥匙串：`mi_fitness_auth_<uid>_*`
- 拉取：`_pull_proc[user_id]` 独立进程 + 独立状态
- 缓存：`data_source` 缓存按用户分 key
- LLM 日志：`memory_data/<user_id>/usage_log.jsonl`
- 请求：所有接口带 `user_id`，`threading.local()` 防并发串用户
- 子线程：后台线程全部显式传 `user_id`
