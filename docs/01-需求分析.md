# MiHealth 睡眠智能体系统 · 需求分析

> 版本：v2.0
> 日期：2026-10-20
> 作者：Sharkkkkkkkll

## 1. 项目背景

### 1.1 问题定义

现代人普遍存在睡眠不规律、作息紊乱的问题。小米手环等可穿戴设备能够采集睡眠、心率、血氧、压力等健康数据，但数据停留在「查看」层面，缺乏**基于数据的主动干预**。

本项目旨在构建一个「睡眠智能体」系统，实现：

- 自动采集小米手环健康数据
- 基于历史数据 + 实时心率，AI 规划入睡时间
- 在起床窗口内，根据浅睡/REM 期智能叫醒
- 通过反馈闭环持续优化预测模型

### 1.2 目标用户

- 使用小米手环/手表等支持心率广播的设备
- 作息不规律，希望改善睡眠质量
- 需要「在合适的时间被叫醒」而不是被闹钟强行打断深睡
- 愿意通过 App 设置作息目标、授权 AI 决策

### 1.3 核心价值

1. **数据驱动**：不拍脑袋定作息，基于 90 天历史数据学习个人睡眠规律
2. **AI 决策 + 规则兜底**：LLM 做情景判断和策略选择，规则引擎保证系统可靠
3. **端到端闭环**：数据采集 → 分析 → 决策 → 执行 → 反馈 → 进化
4. **多用户隔离**：支持多人使用，数据、记忆、AI 决策互不干扰
5. **BLE 直连**：App 直接连接手环，锁屏整晚保活，不依赖第三方心率 App

## 2. 用户故事

### 2.1 睡前提醒

> 作为用户，我希望在入睡前收到提醒，这样我能提前准备，不会熬夜。

**验收标准**：
- 入睡时间前 60/40/30/20/10 分钟各提醒一次
- 提醒文案由 AI 生成，结合当天活动量、心率、睡眠质量
- 提醒通过系统闹钟全屏响铃，App 被杀也能响

### 2.2 AI 睡眠规划

> 作为用户，我希望 AI 根据我的历史睡眠数据，自动规划今晚几点睡。

**验收标准**：
- 基于 90 天睡眠数据学习个人入睡/起床规律
- 结合生理困意锚点（S）和起床倒推锚点（P）给出推荐
- 支持手动设置起床时间范围，AI 在范围内决策
- 白天小睡、参数变化、新的一天会触发重新规划

### 2.3 智能闹钟

> 作为用户，我希望在起床窗口内，AI 在浅睡/REM 期叫醒我，这样醒来更清醒。

**验收标准**：
- 窗口开始前绝不叫
- 窗口内检测到浅睡/REM 信号 → 渐进式响铃
- 窗口内无浅睡 → 深睡保护 / 保底时刻强制叫醒
- 保底闹钟不依赖 App 存活，系统级保证
- 唤醒后 30 秒确认，未醒则疯狂震动 + 最大音量

### 2.4 健康数据可视化

> 作为用户，我希望在手机上查看我的睡眠、心率、血氧、压力数据。

**验收标准**：
- 总览：步数、睡眠、静息心率、压力
- 睡眠：总览/单日、睡眠曲线、睡眠心率、血氧
- 心率：全天心率详情
- 更多：累计统计、运动记录、睡眠目标、心率广播

## 3. 功能需求

### 3.1 数据采集层

| 功能 | 说明 |
|---|---|
| 小米手环数据导出 | 通过米桥（Mi Fitness Data Bridge）拉取云端数据 |
| 扫码登录 | 支持米家 App 扫码登录，获取小米账号凭据 |
| 增量同步 | 首次全量 90 天，后续增量同步（today-7 重叠窗） |
| 滚动窗口 | 导出 JSON 恒为最近 90 天，避免文件无限膨胀 |
| 多用户数据隔离 | 按 user_id 隔离记忆、数据、数据库 |
| 多用户拉取隔离 | 每个账号独立拉取进程与状态，互不阻塞 |

### 3.2 Agent 决策层

| 功能 | 说明 |
|---|---|
| 睡眠模式学习 | 圆周统计学习入睡/起床规律，支持双相检测 |
| 睡眠规划 | S/P 双锚点 + early/late 耐受画像 + 起床护栏 |
| 情景判断 | LLM 判断今晚属于正常/负债/质量差/硬事夜 |
| 睡前提醒 | P60-P10 五弹 + STAY/HR/OD 实时事件 |
| 智能闹钟 | wake_pack 策略 + 浅睡/REM/深睡保护/保底 |
| 反馈复盘 | 唤醒后比对预测 vs 实际，更新 memory |

### 3.3 手机端执行层

| 功能 | 说明 |
|---|---|
| 4 Tab 界面 | 总览/睡眠/心率/更多 |
| 系统级闹钟 | setAlarmClock 全屏响铃，App 被杀也响 |
| 心率广播 | BLE 直连手环实时心率，1s 级更新 |
| BLE 保活 | 前台服务 + WakeLock/WifiLock + autoConnect 重连 |
| 智能闹钟引擎 | WakeEngine 状态机，本地实时决策 |
| 本地心率曲线 | 整晚心率曲线本地存储，30 天自动清理 |
| 二维码登录 | 首次启动扫码登录，支持多用户 |
| 多账号切换 | 每台手机独立登录，各自显示各自数据 |

## 4. 非功能需求

| 类别 | 需求 |
|---|---|
| 可靠性 | 闹钟不依赖 App 存活，系统级保证；LLM 失败退回规则中心值；BLE 断线自动重连 |
| 性能 | 同步 < 2 分钟；心率 1s 实时；闹钟零同步延迟 |
| 安全 | 凭据存系统钥匙串；多用户数据/记忆/AI 决策隔离；导出文件权限控制 |
| 可维护性 | 规则引擎 + LLM 决策分层；幂等保护；启动恢复 |
| 成本 | 优先本地计算，LLM 调用最小化（事件驱动，不轮询） |
| 兼容性 | Android 8.0+（minSdk 26）；小米手环 10 实测 |

## 5. 约束与假设

### 5.1 技术约束

- 小米手环数据通过非官方接口获取，可能随小米服务变化失效
- 心率广播依赖手环开启心率广播，App 通过 BLE 直连读取
- Android 后台限制（MIUI 冻结）需要用户手动加白名单

### 5.2 业务假设

- 用户作息可以通过 90 天历史数据学习
- 心率回升 + 波动可以作为浅睡/REM 的近似信号（非 EEG 精确分期）
- 起床时间范围由用户设定，AI 在范围内决策
