## 2. 数据采集与多账号隔离

### 2.1 米桥搭建

**测试数据**：

- 小米手环 10 导出
- 时间范围：2026-07-11 ~ 2026-10-20
- 数据量：约 127,000 条
- 类型：daily_activity / sleep / heart_rate / spo2 / stress / workouts

**测试现象**：

- 首次全量拉取成功，约 2 分钟完成
- 后续增量同步正常，`today-7` 重叠窗无重复
- 滚动窗口保持最近 90 天，文件不无限膨胀
- 扫码登录成功，token 写入系统钥匙串

**改进方法**：

- 增加 `--force-full` 强制全量
- 增加 JSON 写一半时读取重试（3 次，间隔 1s）
- 增加 `_prune_old_jsons` 清理旧快照

### 2.2 多账号隔离

**测试数据**：

- 小夏账号：`3035284168`
- 妈妈账号：`3267629591`

**测试现象**：

- 两个账号扫码登录成功，token 按 userId 写入钥匙串
- 两个账号数据目录独立：`JSON/<user_id>/`
- 两个账号记忆目录独立：`memory_data/<user_id>/`
- 两个账号同时拉取互不阻塞
- 妈妈手机登录妈妈账号，只显示妈妈数据

**发现的问题**：

- 账号目录为空时页面全空（数据还在根目录）
- 两个账号同时拉取时 `/api/pull_status` 会互相干扰
- Agent 后台线程可能读到根目录或别人的数据

**改进方法**：

- `find_latest_json()` 增加账号目录为空时回退根目录
- `/api/pull` 和 `/api/pull_status` 按 user_id 独立进程/状态
- `data_source` 缓存按用户分 key，`threading.local()` 防并发串用户
- 所有后台子线程显式传 `user_id`
- LLM 用量日志按用户目录分开

## 3. 睡眠规划

### 3.1 S/P 双锚点

**测试数据**（2026-10-13）：

```
S=02:43 P=01:30 early=82 late=73
→ lo=01:21 hi=03:00 center=01:30
→ 护栏 03:00 全链路兜底
```

**测试现象**：

- S 锚点（生理困意）计算正确
- P 锚点（起床倒推）计算正确
- early/late 耐受画像生效
- 起床护栏生效，推荐不超过 03:00

**改进方法**：

- 耐受画像从固定值改为动态 EMA 学习
- 增加白天小睡抵扣逻辑
- 增加凌晨保护窗口（00:00-06:00 不因新的一天重规划）

### 3.2 白天小睡与精力

**测试数据**（2026-10-16）：

```
凌晨 00:31：energy_pct=8.6%，should_awake=1043，cum_awake=953
23:06：energy_pct=5.0%，should_awake=1043，cum_awake=1043
```

**测试现象**：

- 白天小睡后精力回升但不虚高
- 凌晨精力不显示 100%
- 今天没睡时 `cum_awake=now_min`
- 体力按时间慢慢恢复，不瞬间回满

**发现的问题**：

- 凌晨精力曾显示 100%（满格战神）
- 白天睡觉后精力没算恢复

**改进方法**：

- `_cumulative_awake` 今天没睡眠记录时返回 `now_min`
- 白天小睡计入总睡眠，抵扣清醒压力
- 体力改为按时间慢慢恢复

## 4. 睡前提醒

### 4.1 固定五弹

**测试数据**（2026-10-17 日志）：

```
[Pack] 重建闹钟包: bed=01:00 ver=... items=['P60', 'P40', 'P30', 'P20', 'P10']
[PreGenNext] 生成完成 P60 @ 23:55:35
[PreGenNext] 生成完成 P40 @ 00:16:00
[PreGenNext] 生成完成 P30 @ 00:25:45
[PreGenNext] 生成完成 P20 @ 00:36:03
[PreGenNext] 生成完成 P10 @ 00:46:02
```

**测试现象**：

- P60/P40/P30/P20/P10 五弹全部正常
- AI 文案在弹前 5 分钟生成
- 文案生成失败时本地模板兜底
- 闹钟包 version 变化后手机自动重定

**发现的问题**：

- 服务重启后闹钟规划丢失
- 偶发 JSONDecodeError
- 智能闹钟弹窗文案显示“AI 生成失败”

**改进方法**：

- 增加 `_startup_recovery()` 启动恢复
- `data_source.load()` 增加读取重试
- 智能闹钟文案改为固定唤醒条件，不生成

## 5. 智能闹钟

### 5.1 唤醒策略生成

**测试数据**（2026-10-16）：

```
wake_pack_last: {
  "strategy": "deep_protect",
  "deep_protect_trigger": "00:15",
  "hr_baseline": 84,
  "awake_confirm": {"hr_rise_pct": 15, "duration_sec": 30}
}
```

**测试现象**：

- 整晚心率曲线上传成功
- Agent 返回 wake_pack 策略
- 窗口开始前绝不叫
- 窗口结束保底响过之后绝不叫
- 正常叫醒后取消保底闹钟，防双响

**发现的问题**：

- 跨天时曲线文件按日期分开，凌晨数据可能丢失
- 唤醒策略日志只有英文，用户看不懂
- 保底闹钟响后没上传复盘

**改进方法**：

- `WakeEngine` 合并启动日期 + 当天日期曲线再上传
- 唤醒策略日志中英双语输出
- 保底闹钟响铃时也上传 `sendReview("fallback_only")`

### 5.2 渐进式响铃

**测试现象**：

- 每 5 秒升高一档音量
- 初始音量约 30%，逐步升到 100%
- 30 秒后进入确认阶段
- 未确认醒来 → 疯狂震动 + 最大音量

**改进方法**：

- 音量控制走 `STREAM_ALARM`，不被系统音量限制
- 30 秒确认判定由 Agent 根据历史数据出具

## 6. BLE 心率直连

### 6.1 扫描与连接

**测试现象**：

- 扫描到手环设备
- 连接成功显示 `BLE直连 · 实时心率 xx bpm`
- 锁屏整晚心率不断
- 断线后自动重连

**发现的问题**：

- 扫描结果包含很多不常用设备
- 已配对设备直接列出后容易点错设备
- 扫描时长 12 秒太短，可能抓不到广播

**改进方法**：

- 已配对设备直接列出（不用等广播）
- 扫描时长从 12 秒提到 25 秒
- 结果按小米/手环/心率服务优先排序
- 后续可只显示带 `0x180D` 心率服务的设备

### 6.2 锁屏保活

**测试现象**：

- 前台服务 + `PARTIAL_WAKE_LOCK` + WifiLock 保活
- `autoConnect=true` 系统级重连
- 5s-30s 指数退避重连
- 20s 假死检测，90s 强制重连

**改进方法**：

- 从 Hyperate WebSocket 改为 BLE 直连
- 增加 `HrForegroundService` 独立保活
- 心率广播开关开着就全量记录
